# 管理端服务连接检测

## 接口与权限

`GET /admin/system/health`

携带 `Authorization: Bearer <JWT>`，仅 ADMIN 可访问；EDITOR、USER 返回 HTTP 403，未登录或旧版本 JWT 返回 HTTP 401。
没有新增匿名健康检查入口，也没有绕过账号启用状态或 token_version 的认证规则。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "checkedAt": "2026-10-23T04:00:00Z",
    "database": { "status": "UP", "message": "连接正常" },
    "redis": { "status": "DOWN", "message": "连接检测失败" },
    "smtp": { "status": "DISABLED", "message": "邮箱验证码功能未启用" }
  }
}
```

以上只是响应示例，不代表当前部署环境的实际状态。
检测正常取得结果时，即使依赖的 status 为 DOWN，仍返回 HTTP 200、code 200；依赖状态不等于接口执行结果。
checkedAt 是实际检测完成时间，采用带时区的 ISO 时间；缓存命中时不伪造新的检测时间。

## 状态含义

| status | 含义 |
| --- | --- |
| UP | 本次连接检查通过，不保证所有业务功能正常 |
| DOWN | 本次连接检查失败、未得到预期响应或检测超时，不等于证明服务进程已停止 |
| DISABLED | 邮箱验证码功能关闭，未连接 SMTP |
| UNCONFIGURED | 邮件组件、发件地址、SMTP 主机、账号或密码缺少必要配置，未连接 SMTP |
| NOT_CHECKED | 当前邮件实现不支持检测、检测工作线程仍繁忙或检测被中断，未取得确定结论 |

## 检查内容

- 数据库：复用现有 DataSource，获取连接后执行 JDBC `isValid(2)`，验证期限为两秒；通过 try-with-resources 归还连接，不读取或修改业务记录。
- Redis：复用现有 StringRedisTemplate 执行 PING，预期 PONG，不写测试键；连接由模板管理并释放。
- SMTP：复用现有 JavaMailSenderImpl 执行 testConnection()，检查配置的服务器连接，不调用 send()，不会发送验证码、消耗验证码发送额度或检查收件箱投递。
- SMTP 检测仍使用现有 TLS、认证、连接和读写超时配置；不能用端口可连代替真实 SMTP 连接，也不关闭证书校验。
- 不支持 testConnection() 的自定义 JavaMailSender 返回 NOT_CHECKED，不强制类型转换、不发送测试邮件。

## 缓存与超时

- 每个应用实例在内存中缓存结果 30 秒，不依赖待检查的 Redis 保存缓存，也不新增表或依赖。
- 首次查询或缓存过期时执行检测，刷新在同一服务锁内完成，避免多个请求重复探测；页面手动刷新也不会绕过服务端缓存。
- 三项检查使用独立线程并行发起，共享约十秒的等待期限，不是每项串行等待十秒。
- 数据库获取连接仍受现有连接池配置影响；十秒到期后接口取消对应 Future 并返回超时结果，不修改全局数据库或 Redis 超时参数。
- 取消操作不能保证立即终止所有底层网络调用。专用线程池最多三个线程且没有等待队列；线程仍被外部调用阻塞时，新任务返回 NOT_CHECKED，不无限增加线程或积压任务。
- 十秒期限不包括 JWT 认证数据库查询、HTTP 网络传输或线程调度时间，不能视为整个请求的严格十秒 SLA。
- 应用停止时销毁检测线程池；启动时不主动执行连接检测。

## 安全与失败展示

响应只包含预定义状态、简短说明和检测时间，不返回数据库 URL、SMTP 或 Redis 主机、用户凭据、授权码或原始异常。
检测失败日志只记录依赖类型和异常类名，不记录异常原文或堆栈。

特别注意：当前 JwtAccountAuthoritiesConverter 每次认证都需要查询数据库。数据库故障可能使请求在进入检测 Controller 前就失败，即使存在检测缓存，也不能跳过认证读取缓存。
前端对此显示“无法获取检测结果”或请求超时，不将 HTTP 错误、网络错误、401/403 直接映射成全部依赖 DOWN。
若以后需要数据库故障时仍可读取详细状态，应另行设计受内网访问控制的监控入口，本次未开放这样的接口。

## 前端接入

设置页“系统信息”中的“当前服务连接情况”由 ADMIN 首次进入时请求上述接口，可手动刷新；EDITOR 仅显示权限提示，不请求该接口。
前端最多等待十五秒，为后端十秒检测及结果传输留出余量，超时或请求失败时清除当前结果并显示检测不可用；页面卸载或停用时取消未完成请求。
检测不修改个人偏好，不触发偏好保存，也不影响未保存草稿；检测时间由服务端返回，页面按浏览器本地时区展示。

## 实现位置与验证

- acgbox-app：SystemHealthController、SystemHealthService、SystemHealthServiceImpl、SystemHealthConfig。
- acgbox-model：SystemHealthVO、DependencyHealthVO。
- acgbox-user：在既有 SecurityConfig 中限制 `/admin/system/**` 为 ADMIN。
- ACGBox-UI：复用现有 HTTP 封装、认证存储及 AdminIcon，在原设置页局部接入，不新增监控页面。

自动化测试覆盖连接释放、单项失败隔离、缓存到期、SMTP 关闭及未配置、不支持的邮件组件、超时取消、线程池饱和、管理员权限与认证数据库不可用，以及前端失败、刷新和取消流程。
测试使用模拟数据库、Redis 与 SMTP，不代表已验证实际部署环境的连通性；界面截图检查同样使用模拟接口数据，不发送真实邮件。
