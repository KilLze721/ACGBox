# 外部私有配置

## 文件分工

- `acgbox-app/src/main/resources/application.yml` 保持原样，作为程序的公共配置。
- `D:/ACGBox-config/application-secrets.yml` 保存本机私有配置，不在 Git 仓库或 resources 中，不会随项目打包。
- `config/application-secrets.example.yml` 是不含真实密钥的示例文件，可以提交。
- `.gitignore` 同时忽略任何位置的 `application-secrets.yml`，防止以后误将私有文件复制进仓库并正常添加到 Git。

私有文件的 Windows 权限限制为当前创建账号、SYSTEM 和 Administrators，不向普通用户组开放。
不要使用 `git add -f` 强制提交私有文件，也不要将它复制到静态资源目录或公开下载目录。

## 本机 IDEA

`acgbox-app` 模块对应的 `AcgBoxApplication` 启动配置使用以下 VM options：

```text
-Dspring.config.additional-location=file:D:/ACGBox-config/application-secrets.yml
```

当前 JWT 密钥从原 IDEA 环境变量配置迁移到私有文件，不重新生成。
IDEA 环境变量中的同名 JWT 配置在确认迁移后移除，避免它优先于私有文件，使修改文件后看起来没有生效。
IDEA 若未刷新外部修改的启动配置，可重新打开项目，或在 Run/Debug Configurations 中确认此参数。
旧的 `acgbox-content` 模块运行配置不在本次调整范围内，运行后端请选择 `acgbox-app` 对应的配置。

## JAR 部署

先将私有配置单独部署到目标机器，再运行 JAR；本机示例命令：

```powershell
java -jar acgbox-app-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:D:/ACGBox-config/application-secrets.yml
```

Linux 示例路径和命令：

```bash
java -jar /opt/acgbox/acgbox-app.jar --spring.config.additional-location=file:/etc/acgbox/application-secrets.yml
```

JAR 文件名以实际构建结果为准。Linux 配置文件应仅授权服务账号和必要管理员读取，例如由服务账号拥有并设置权限 600。
部署路径通过启动参数指定，不写死在后端代码中。每个环境分别维护自己的数据库、SMTP、Redis 和 JWT 密钥。
未使用 `optional:`：指定文件不存在时启动失败，不会悄悄忽略私有配置。
更新私有配置后需要重启，不是动态热更新。

## 配置填写

日常只需要修改 `D:/ACGBox-config/application-secrets.yml`；该文件和仓库中的示例文件均已逐项添加中文注释。
示例文件只用于参考，不要将真实密钥、邮箱授权码或数据库密码填写进去。

建议按以下顺序填写：

1. 保留已经迁移的 JWT 密钥，除非确实需要轮换，不要改动。
2. 确认 `spring.datasource` 中的数据库地址、数据库账号和该账号密码。
3. 填写 Redis 地址、端口和认证信息，默认逻辑数据库编号为 0。
4. 在邮件服务商开通 SMTP，填写服务器地址、端口、认证账号及授权码。
5. 填写 `ACGBOX_MAIL_FROM`，通常与 SMTP 账号相同，不能只填用户名而将此项留空。
6. 按服务商要求配套设置端口和 TLS：常见 587 为 STARTTLS=true、SSL=false，465 为 STARTTLS=false、SSL=true。
7. 确认邮件和 Redis 均已配置后，再将 `ACGBOX_ACCOUNT_EMAIL_ENABLED` 改为 true 并重启后端。

实际参数以你的服务商和服务器配置为准，注释中的常见端口不是对任何 SMTP 服务的固定要求。
保留键名和 YAML 缩进；字符串建议保留双引号，布尔开关填写 true 或 false，端口和数据库编号填写数字。
当前私有文件中的 `ACGBOX_MAIL_FROM` 显式为空时，原配置的默认用户名不会生效，邮件功能会提示尚未配置。

私有文件中的 `ACGBOX_JWT_SECRET` 等属性会被原文件的同名占位符解析。
它们是 Spring 配置属性，不是新增的操作系统环境变量；业务代码通过 Spring 配置读取即可。
系统环境变量、JVM 属性和命令行中若存在同名属性，可能覆盖文件值，排查时检查所有启动来源。
数据库属性在原文件中是硬编码值，需在私有文件使用 `spring.datasource` 下的同名属性覆盖，不能只增加未被引用的 `ACGBOX_DB_PASSWORD`。

邮件功能目前保持关闭，填写正确的 SMTP 账号、授权码及 Redis 连接信息后，将 `ACGBOX_ACCOUNT_EMAIL_ENABLED` 改为 true 再重启。
SMTP 587 通常使用 STARTTLS；SMTP 465 通常设置 STARTTLS=false、SSL=true，以服务商要求为准。
修改 JWT 密钥会导致旧 JWT 签名校验失败，并影响旧密钥生成的邮箱验证码摘要，不应无意更换。

## 安全边界

私有文件不会进入本项目的正常 Git 提交或 JAR，但仍是明文文件，需要妥善管理权限和备份。
本次没有修改或清理原 `application.yml`，其中原本硬编码的数据库密码仍存在于源文件及可能的 Git 历史中。
不提交当前私有文件不等于撤回过去已经公开过的凭证；真实凭证若已泄露，需要单独轮换。

参考：[Spring Boot 外部配置](https://docs.spring.io/spring-boot/4.0/reference/features/external-config.html)。
